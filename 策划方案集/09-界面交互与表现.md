## 二、相机

相机不再因上下车切换第一/第三人称。徒步和驾驶统一采用枢轴+弹簧臂防穿墙的3米近距离右后肩第三人称，玩家角色占据左下角主要前景；按住右键平滑收近至约2米右肩越肩构图。驾驶时同时显示半透明抛物线，徒步时不显示轨迹，商品直接沿中央白点准星方向投出；空手时右键只负责越肩观察。只有头顶悬浮分区牌会在过近遮挡镜头时暂时隐藏，货架、墙体、地台和门禁不参与。主机和每个客户端只驱动自己的本机相机。鼠标环绕俯仰范围为-66°~+20°；涉及本机玩家的碰撞仍触发相机震动。

## 三、HUD布局

- **左上**:代购清单面板(按分区分组,爆款专区置顶;入车标绿划线;实时状态与库存)+已到手货值
- **顶中**:大号倒计时+阶段名(打烊冲刺变橙、宽限变红)
- **中下**:红色粗体情境提示(F推车/按住E搜货…)+长按进度条
- **左下**:状态行显示Q雷达、右键当前投掷商品、Ctrl稳住、**空格角色技能**冷却；另有角色技能冷却圆环、体力槽(绿)和失衡槽(橙)
- **右下**:驾驶时只显示车斗内非订单商品；所有手持商品始终进入轮盘。无可投掷商品时隐藏；中心高亮当前商品并显示直击失衡，环上用统一颜色、短标签与矢量图标区分四类效果
- **屏幕中心**:保留带暗边的白点准星；驾车按住右键时额外显示半透明白色抛物线及落点，徒步第三人称不显示轨迹、直接按白点方向投掷
- **右下**:三行红色粗体键位速查
- **屏幕边缘**:马德胜「余光」的威胁方向箭头(仅该角色显示,越近越亮,即将命中时闪白)
- 教学模式另有顶部绿色大字分步指引
- 商品模型不再生成名称标签；玩家瞄准具体商品时才显示1.5倍尺寸的“名称＋投掷效果＋失衡值”注释卡，选中投掷商品仍由右下轮盘明确显示
- 徒步始终显示本机世界角色、双手和真实手持商品；旧第一人称镜头手臂不再启用，避免联机主客机因挂车状态不同步进入两套表现分支
- 碰撞、肘击与技能拟声字幕根据镜头距离做带上下限的动态缩放：远处适度放大、近处收小但不消失；本机头顶或落到镜头后方的字幕会移入镜头前下方的安全可读区
- NPC、购物车与环境产生的世界字幕必须真实位于相机前方、屏幕范围内且未被墙体或货架遮挡，否则不渲染
- 局内HUD 在开始界面阶段**整体隐藏**(开局前显示计时与体力条没有意义)

### 3.1 四队改版HUD（待审阅）

- 左上清单改为固定队色边框，显示共享订单；每行标记由哪名队员/AI携带、队伍车内数量和已扫码数量。
- 顶部增加12秒准备阶段、中央压轴“封闭/预警/已开放”和“已发现收银N/4”。
- 屏幕边缘显示队友方向、距离、倒地、冻僵和准备结算状态；雾区内队友在6米内保留弱轮廓。
- 收银台只有进入12米且获得视线后才写入队伍情报；开放为绿色收银图标，关闭为红色卷帘图标。
- 增加中键情境标记，支持商品、区域、敌人和收银台四种语义，供无语音队伍分工。
- 区域机制各使用单一常驻提示：冷冻计量改为屏幕右侧淡蓝色技能CD式圆环，直接显示百分比/剩余冻僵秒数；另有易碎裂纹角标、雾区能见度边缘和中央开门预警，不把所有机制堆成文字教程。
- 个护区由局部`FogVolume`承担真实体积雾，边缘约2.2米渐入、深入后清晰观察距离约5米；不复用散落投掷物的块状全屏遮罩。
- 《21》的趣味商品不增加机制角标或额外教程；HUD只沿用商品名、所属订单类别和既有四类投掷图标。包装笑点留在近景模型、拿起短提示与结算账本中。

## 五、碰撞与动作表现

- **拟声词飘字**:80号粗体大字,"哐当!!/咣!!!/duang~!!/嘭!!!"随机开头;撞行人追加"人仰马翻!/鞋都撞飞了!/菜篮子保卫战失败!"等
- **双手小球**:所有角色两只球形手,四姿态(走路摆臂/推车扶把/翻找扒拉/托举搬运);肘击时后拉蓄力→猛捅→拳头膨胀2倍
- 倒地为白盒布娃娃平替(弹跳式倒伏),正式版升级物理布娃娃

## 六、开始界面与联机大厅(v0.15 重做为分级导航)

> **四队改版目标**：房间页将由自由成员列表改为蓝/橙/绿/紫四列队伍卡，每列2席。玩家自行点击空席组队，空位显示“开局由AI补充”；删除个人8色配色板，队色由team_id固定。名号与角色仍可修改，同队允许重复角色。房主开始后先进入等待室12秒准备阶段，而不是点击即开放卖场。完整大厅流程见《20·二/六》。下文保留当前v0.18.2界面作为回退基线。

大红标题「疯抢星期五」+Slogan「文明,打烊之前有效」,版本号常显(vX.Y与协议版本双校验)。

**设计原则:不把所有内容堆在初始菜单**。参照常见联机游戏的信息架构,
主界面只放三个入口,其余按需下钻,每一层都能返回上一层:

```
主界面(只有三个按钮 + 角落"退出游戏")
 ├─ 单人游戏 → 选择角色页 ──────────────→ 开始游戏
 ├─ 多人联机 → 联机页 ┬ 创建房间 ────→ 房间页 ─→ 开始对局
 │                    └ 加入游戏 → 输入IP页 → 房间页(等房主)
 └─ 教学模式 ─────────────────────────→ 直接开局
```

### 6.1 选择角色页(单人游戏)

- 左:三张角色卡(选中项按角色主色描边高亮),下方详情显示
  **角色简介 / 台词 / 空格主技能(含冷却与全部代价) / 被动**
  —— 代价必须在开局前就让玩家看见,否则技能无法"10秒学会"
- 右:我的名号(≤8字,方括号转义防富文本注入)+ 8色配色板 + 开发者选项(大妈数量滑块)
- 底:返回 / 开始游戏

### 6.2 联机页与输入IP页

- 联机页:常显本机IP与端口 + 「创建房间」「加入游戏」两个按钮 + 返回
- 输入IP页:单独一页只做一件事(填房主IP → 连接),回车即连 + 返回

### 6.3 房间页(大厅)

- 左:成员列表,每行 `色块 + 序号 + 名号 + 角色与主技能 + 房主标记`,标题显示人数 N/6
  - **角色公开**(《14·九》):技能是战术信息,应当让对手看见以便应对
- 右:我的名号与配色 + 我的角色(紧凑版角色卡,可在房间里随时改)
- 底:离开房间 / 房主独有「开始对局(N人)」(不足2人禁用)
- 房间内改名、换队、换角色都会实时推送给全房间

底部为整宽状态提示区(建房成功提示、防火墙排障四步、版本不一致警告等)。

> 实现位于 `scripts/start_menu.gd`(独立 Control 模块,页面栈 `_pages` + `_go()`);
> `hud.gd` 只做信号转发,不再承担菜单构建。角色档案逻辑在 `scripts/player_profile.gd`。
>
> **踩坑记录**:代码创建的 `Control` 初始 `size` 为 0,只调`set_anchors_preset()`
> 会留下 offsets,导致所有子节点堆到屏幕左上角(v0.14 及之前的菜单一直如此,
> 因为 UI 从未被人眼确认过)。必须用 `set_anchors_and_offsets_preset()`。
>
> **UI 目视回归钩子**:`WHITEBOX_MENU_PAGE=solo|mp|join|room` 直接打开指定页面,
> 配合 `WHITEBOX_SHOT=<png>` 即可一条命令截取任意一层界面——UI 无法被无头断言覆盖,
> 只能靠截图确认,这个钩子把"确认 UI"从手工操作变成可重复的命令。
