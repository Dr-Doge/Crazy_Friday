## 一、键位总表

| 键 | 功能 |
|------|------|
| 鼠标 | 第三人称自由视角(默认捕获,Esc开关) |

| W/S(推车) | 沿车头前进 / 刹车·倒车 |

| R | 放下手中物品 |
| 鼠标左键 | 肘击(朝镜头方向,无CD耗4体力) |

| 鼠标右键 | 驾驶时进入约2米右肩瞄准并显示抛物线，松开投掷；脱车时仅将第一人称从75°放大至约58°，松开无动作 |

## 二、相机

相机按驾驶状态切换两套构图。驾驶购物车时采用枢轴+弹簧臂防穿墙的3米近距离右后肩第三人称，玩家角色占据左下角主要前景；按住右键平滑收近至约2米右肩并以玩家上身为瞄准中心。只有头顶悬浮分区牌会在过近遮挡第三人称镜头时暂时隐藏，货架、墙体、地台和门禁不参与。脱离购物车时立即切换为75°第一人称并停用告示牌LOD，所有场景实体保持显示；隐藏本机角色模型但保留白点准星和货架商品射线互动。按住右键只将视野缩小至约58°，不显示投掷轨迹，也不会在松开时投掷。鼠标环绕俯仰范围为-66°~+20°。**涉及本机玩家的碰撞触发相机震动**(强度随车速,平方衰减);联机时只震当事玩家所在的机器。

## 三、HUD布局

- **左上**:代购清单面板(按分区分组,爆款专区置顶;入车标绿划线;实时状态与库存)+已到手货值
- **顶中**:大号倒计时+阶段名(打烊冲刺变橙、宽限变红)
- **中下**:红色粗体情境提示(F推车/按住E搜货…)+长按进度条
- **左下**:状态行显示Q雷达、右键当前投掷商品、Ctrl稳住、**空格角色技能**冷却；另有角色技能冷却圆环、体力槽(绿)和失衡槽(橙)
- **右下**:仅驾驶购物车时显示商品轮盘，中心高亮当前商品并显示直击失衡；脱车立即隐藏；环上用统一颜色、短标签与矢量图标区分爆裂/湿滑/遮挡/定身四类
- **屏幕中心**:仅保留一个带暗边的白点准星；按住右键时额外显示带暗边的半透明白色抛物线及落点，松开后商品沿同一组物理参数投出
- **右下**:三行红色粗体键位速查
- **屏幕边缘**:马德胜「余光」的威胁方向箭头(仅该角色显示,越近越亮,即将命中时闪白)
- 教学模式另有顶部绿色大字分步指引
- 商品进入任意购物车车斗后隐藏自身头顶名称，离开车斗立即恢复；选中商品仍由右下轮盘明确显示
- 徒步第一人称使用独立的镜头手臂表现，继承走动、搜货、搬运、稳住与肘击动作；本机世界模型继续隐藏，避免胶囊和原始手部贴脸穿模
- 第一人称双臂整体位于中央交互提示两侧，圆球拳头与手持商品保持同一高度；商品尺寸按最长边等比收纳在两拳之间，而不是悬挂在胳膊底端。手持表现只保留极轻微呼吸起伏，不继承角色转身、地形和网络插值抖动；肘击前送时右拳可夸张放大至2.35倍。真实商品仍维持权威持有状态但对本机隐藏，放下、装车或切回第三人称时立即恢复
- 碰撞、肘击与技能拟声字幕根据镜头距离做带上下限的动态缩放：远处适度放大、近处收小但不消失；本机头顶或落到镜头后方的字幕会移入镜头前下方的安全可读区
- 第一人称只有玩家自身反馈可以进入镜头安全区；NPC、购物车与环境产生的世界字幕必须真实位于相机前方、屏幕范围内且未被墙体或货架遮挡，否则不渲染
- 局内HUD 在开始界面阶段**整体隐藏**(开局前显示计时与体力条没有意义)

## 六、开始界面与联机大厅(v0.15 重做为分级导航)

大红标题「疯抢星期五」+Slogan「文明,打烊之前有效」,版本号常显(vX.Y与协议版本双校验)。

**设计原则:不把所有内容堆在初始菜单**。参照常见联机游戏的信息架构,
主界面只放三个入口,其余按需下钻,每一层都能返回上一层:

```
主界面(只有三个按钮 + 角落"退出游戏")
 ├─ 单人游戏 → 选择角色页 ──────────────→ 开始游戏
 ├─ 多人联机 → 联机页 ┬ 创建房间 ────→ 房间页 ─→ 开始对局
 │                    └ 加入游戏 → 输入IP页 → 房间页(等房主)
 └─ 教学模式 ─────────────────────────→ 直接开局
```

### 6.1 选择角色页(单人游戏)

- 左:三张角色卡(选中项按角色主色描边高亮),下方详情显示
  **角色简介 / 台词 / 空格主技能(含冷却与全部代价) / 被动**
  —— 代价必须在开局前就让玩家看见,否则技能无法"10秒学会"
- 右:我的名号(≤8字,方括号转义防富文本注入)+ 8色配色板 + 开发者选项(大妈数量滑块)
- 底:返回 / 开始游戏

### 6.2 联机页与输入IP页

- 联机页:常显本机IP与端口 + 「创建房间」「加入游戏」两个按钮 + 返回
- 输入IP页:单独一页只做一件事(填房主IP → 连接),回车即连 + 返回

### 6.3 房间页(大厅)

- 左:成员列表,每行 `色块 + 序号 + 名号 + 角色与主技能 + 房主标记`,标题显示人数 N/6
  - **角色公开**(《14·九》):技能是战术信息,应当让对手看见以便应对
- 右:我的名号与配色 + 我的角色(紧凑版角色卡,可在房间里随时改)
- 底:离开房间 / 房主独有「开始对局(N人)」(不足2人禁用)
- 房间内改名、换色、换角色都会实时推送给全房间

底部为整宽状态提示区(建房成功提示、防火墙排障四步、版本不一致警告等)。

> 实现位于 `scripts/start_menu.gd`(独立 Control 模块,页面栈 `_pages` + `_go()`);
> `hud.gd` 只做信号转发,不再承担菜单构建。角色档案逻辑在 `scripts/player_profile.gd`。
>
> **踩坑记录**:代码创建的 `Control` 初始 `size` 为 0,只调`set_anchors_preset()`
> 会留下 offsets,导致所有子节点堆到屏幕左上角(v0.14 及之前的菜单一直如此,
> 因为 UI 从未被人眼确认过)。必须用 `set_anchors_and_offsets_preset()`。
>
> **UI 目视回归钩子**:`WHITEBOX_MENU_PAGE=solo|mp|join|room` 直接打开指定页面,
> 配合 `WHITEBOX_SHOT=<png>` 即可一条命令截取任意一层界面——UI 无法被无头断言覆盖,
> 只能靠截图确认,这个钩子把"确认 UI"从手工操作变成可重复的命令。
