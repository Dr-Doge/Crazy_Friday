# 10 · 局域网联机设计

> 项目:疯抢星期五 | 文档集v1.4 | 对应游戏版本v0.17 | 2026-08-13 | 状态:已立项

---

## 一、总体架构:主机权威 + 种子确定性

- **主机跑全部模拟**:物理、大妈AI、计时、事件、碰撞、计分全在主机;客户端仅发送输入、以插值渲染同步状态
- **世界零传输**:开局只下发一个随机种子+NPC数量+座位号+全员档案——各端用同一种子跑同一段生成代码,货位/清单/大妈/水渍完全一致
- 传输层:ENet UDP,端口7788;协议版本号校验(不一致明确拒绝并提示换exe)。**当前 `NET_VERSION = 7`**
  (v6:购物车全商品轮盘投掷；v7:马德胜双随从世界状态包与新投掷效果同步)

## 二、大厅制(2-6人)

1. 主机点"创建房间"(界面常显本机IP)→进入大厅,房主自己首先出现在成员列表里
2. 其他人(≤5)填主机IP加入;连上后**立即上报自己的档案**(昵称+配色)
3. 主机汇总成员表并广播给所有人,各端显示一致的成员列表:
   **色块 + 座位号 + 昵称 + 房主标记 + 人数 N/6**
4. 大厅内任何人改名或换色都会实时推送,列表即时刷新
5. 主机点"**开始对局**"(≥2人可点)→分配座位(主机0,客户端按加入顺序1-5)→统一开局
6. 开局后迟到连接被拒绝
7. 容错:先建房再加入会自动切换为客户端身份;大厅期间场景树**不暂停**(暂停态ENet轮询不稳,踩坑记录)

## 三、角色档案同步(v0.14 起,v0.15 加入所选角色)

- 档案 = 昵称(≤8字) + 配色索引(8色) + **所选角色 id**,存本机 `user://profile.cfg`,下次启动自动带出
- 昵称在写入前统一清洗:去首尾空白、压掉换行制表、限长,并把方括号替换掉
  (昵称会进开了bbcode 的 `RichTextLabel`,不转义会被当富文本标签解析)
- **消歧由主机统一裁决**:开局前主机对全员昵称与配色做去重
  (撞色顺移到最近空闲色位、重名加序号后缀),消歧结果随开局指令下发。
  各端渲染同一份结果,不会出现"你看到两个蓝色老王、我看到一个"的分歧
- **角色不做消歧**:多人选同一个角色是允许的(角色只影响外貌与技能,不涉及唯一资源);
  但角色 id 会经`CharacterDef.valid_id()`兜底,损坏的存档不会让开局崩溃
- 昵称与配色的作用面:头顶名牌(染本人配色)、购物车标签、超市广播、结算排名
- 角色的作用面:大厅成员列表**公开显示**(技能是战术信息,应当让对手看见)、局内技能行为

## 四、状态同步(拆包保MTU)

| 包 | 频率 | 内容 |
|------|------|------|
| 玩家包 | 20Hz | 全部玩家位姿/姿态/失衡/体力/技能CD/长按进度/**角色技能CD与扎马步·硬直计时** |
| 车辆包 | 20Hz | 全部购物车位姿+闸机高度+计时 |
| 世界包 | 10Hz | 大妈位姿+活动商品(货架未动的跳过;超14条轮转分片) |

- 字符串(提示语/大妈字条/气泡)走"变化才发"的可靠通道
- 事件走可靠RPC:飘字、广播、相机震动(定向)、个人HUD(0.25秒/人)、雷达高亮(定向)、特价生成、水渍/减速区生成、商品消耗移除、大妈离场、结算画面(定向)
- 客户端输入60Hz上送:移动矢量+冲刺/格挡/长按+**本机镜头朝向**(主机按客户端视角解算移动);按键动作(F/E/R/Q/右键/**空格角色技能**/肘击带方向)按事件上送
- 客户端对所有实体做指数插值;实测LAN手感接近本地

> **角色技能与商品投掷一律主机权威**:CD、从车斗取货、投掷命中、失衡与地形效果全在主机结算；客户端只上送选中商品ID与屏幕中心三维射线。商品本体继续通过世界状态包同步，减速区通过可靠事件同步视觉。

## 五、多人对局规则适配

- 6名玩家各用自己的昵称与配色(见第三节),车同色同名
- 每人独立代购清单/计分/技能CD;互偷互撞互肘全部走同一套系统;大妈对所有玩家一视同仁(冲撞/偷窃/追讨)
- 玩家结算即个人终局,其余人继续;结算画面含全场实时排名(按昵称显示,自己标"(你)")

## 六、容错

| 情形 | 处理 |
|------|------|
| 客户端掉线(对局中) | 该玩家退场,购物车留在原地任人打劫,广播提示(用昵称),比赛继续 |
| 客户端掉线(大厅) | 成员列表移除该人并清理其档案,继续等待 |
| 主机掉线 | 全员自动回开始界面 |
| 版本不一致 | 加入时明确拒绝:"请把同一份exe拷给所有人" |
| 连接失败 | 8秒后给出四步排障提示(建房/IP/防火墙UDP7788/同网络) |

## 七、部署要求与已知边界

- 同一路由器/热点;主机首次建房需在Windows防火墙"允许"(UDP 7788)
- 全员使用同一版本exe(文件名带版本号+游戏内版本显示+协议校验三重保障)。
  **当前协议为5，与协议4及更早的exe互不兼容**
- 白盒边界:客户端为纯插值渲染(无预测,LAN下约30-80ms输入延迟);快速投掷轨迹按10Hz商品分片状态同步，客户端不自行判伤;不支持断线重连;互联网联机为后续迭代项

## 八、测试基建

一键入口 `tools/smoke_test.ps1 -Mode mp -Clients 5`(1主机+5客户端满员冒烟,
附带"座位号不重复"断言)。底层环境变量钩子:

| 变量 | 作用 |
|------|------|
| `WHITEBOX_HOST=N` | 建房并凑够 N 名客户端自动开局 |
| `WHITEBOX_JOIN=<ip>` | 自动加入指定主机 |
| `WHITEBOX_PORT=<端口>` | 改绑定端口,便于单机多实例 |
| `WHITEBOX_HOSTJOIN=<ip>` | 复现"先建房再加入"的误操作序列 |

> 注意:`WHITEBOX_HOST` 的值必须等于客户端总数。若设小了,先到的客户端一凑够就开局,
> 后到的会被当作"迟到连接"踢掉,并因重连循环在主机侧刷 ENet 报错。
